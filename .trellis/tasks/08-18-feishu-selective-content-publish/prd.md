# 飞书内容分项写入

## Goal

让本地无限画布和主应用的飞书发布流程支持按内容类别写入，用户可以只写入标题与文案，或者只写入图片与视频，避免不需要的内容覆盖飞书记录。

## Background

- 用户明确要求无限画布和应用端都支持两种分项写入方式：仅文案和标题、仅图片和视频。
- 项目现有生成内容发布通过同一条持久化队列和飞书 CLI 写入多维表格；入口包括主页自动任务、内容审查台单条/批量发布和无限画布发布节点。
- 当前完整发布会写入标题、正文、内容标签、创作来源、车型和附件；已有记录通过 record id 更新，新内容先创建记录再写字段和上传附件。
- 发布队列数据保存在现有 JSON payload 中，因此增加模式不需要修改 PostgreSQL 或 SQLite 表结构。
- 工作区已有与懂车帝路径相关的未提交修改，本任务不得改动或覆盖这些修改。

## Requirements

- R1：无限画布中的飞书发布入口允许选择“仅标题与文案”。
- R2：无限画布中的飞书发布入口允许选择“仅图片与视频”。
- R3：无限画布和主应用的飞书发布入口都提供“完整写入”“仅标题与文案”“仅图片与视频”三种模式。
- R4：后端只向飞书提交所选类别对应的字段，未选择类别的字段不应被写入或清空。
- R5：发布任务状态、失败信息和已有权限隔离行为保持可用。
- R6：保留现有完整发布能力并继续作为默认模式，使未携带新模式的现有请求、自动任务和历史画布工作流保持原行为。
- R7：首页自动任务、内容审查台的单条与批量发布、无限画布飞书发布节点均支持三种模式。
- R8：模式按一次发布任务统一选择；同一批任务中的所有内容使用相同模式，不提供逐条混合选择。
- R9：所选类别的空内容校验沿用现有逐条失败、其余内容继续的部分成功模型；全部内容均无效时任务失败。
- R10：“仅标题与文案”严格只写标题和正文，不写内容标签、创作来源、车型或附件；标题或正文为空的内容不得进入外部写入。
- R11：“仅图片与视频”严格只写附件，不写任何文本或元数据字段；没有图片和视频的内容不得进入外部写入。
- R12：模式必须随持久化队列任务保存，并出现在恢复后的发布状态中；旧队列数据、旧简单任务和旧画布发布节点缺少模式时按完整写入处理。

## Acceptance Criteria

- [x] AC1：从无限画布选择“仅标题与文案”发布时，飞书请求仅包含标题与正文类字段，不包含图片或视频附件字段。
- [x] AC2：从无限画布选择“仅图片与视频”发布时，飞书请求仅包含附件字段，不包含标题或正文类字段。
- [x] AC3：从主应用执行上述两种模式时，飞书请求具有相同的字段隔离语义。
- [x] AC4：未被选中的飞书字段不会因本次发布被清空或覆盖。
- [x] AC5：无效模式和所选类别没有可发布内容时返回明确错误，不创建误导性的成功任务。
- [x] AC6：项目既有自动化基线通过，并新增针对发布模式请求契约与飞书字段映射的确定性覆盖。
- [x] AC7：没有显式选择模式的现有调用仍执行完整写入；用户显式选择后，发布任务及恢复后的界面能显示正确模式。
- [x] AC8：批量发布只选择一次模式，队列去重不会把相同内容但不同模式的任务误判为同一任务。
- [x] AC9：文本模式不执行媒体修复、媒体准备或附件上传，媒体模式不执行内容标签补全、车型选项校验或文本字段回读验证。
- [x] AC10：旧版画布飞书节点加载后升级为带模式选择的新版节点，默认完整写入且保持连线有效。

## Out Of Scope

- 修改飞书 Base 的表结构或字段配置。
- 调用真实飞书生产服务进行默认基线验证。
- 重构与本功能无关的画布、生成或发布流程。

## Technical Notes

- 模式的规范值为 `full`、`text`、`media`；外部请求显式传入非法值时返回 400，只有字段缺失时为了历史兼容默认 `full`。
- 选择性发布沿用现有每用户串行队列、10 条内部批次、逐条失败隔离、显式重试和不自动重放不确定外部写入的规则。
- 可选自定义飞书 CLI 参数继续可用；应用向其提供按模式投影后的 payload、record payload 和模式环境变量，完整模式保持现有数据形态与行为。
