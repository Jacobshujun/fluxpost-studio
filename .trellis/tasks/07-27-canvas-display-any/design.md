# Canvas 展示任何节点设计

## Architecture

实现保持在现有 Canvas 边界内：共享契约、注册表、图校验、执行器和运行规划位于 `src/lib/canvas/`，路由内展示和连接交互位于 `src/app/canvas/page.tsx`，样式继续使用 `src/app/globals.css`。不新增 API、数据库字段、运行状态或业务产物种类。

## Port Contract

`CanvasArtifactKind` 继续只描述真实运行产物：`text`、`images`、`videos`、`socialPost`、`publishJobRef`。新增独立的 `CanvasPortKind = CanvasArtifactKind | "any"`，仅供节点定义和连接 UI 使用，避免把 `any` 伪装成可持久化产物。

集中提供单向兼容判断：类型化输出可以连接同类型输入或 `any` 输入；`any` 不作为输出类型兼容到任意下游。图校验、剪贴板解析、普通连线、快速插入和悬空连线筛选必须共用该判断，不能各自复制条件。

注册 `utility.display-any@1`：标签“展示任何”，工具分类，单个必填且非多路的 `value:any` 输入，无配置字段、能力、绕过映射和输出端口。现有节点定义与旧快照保持不变。

## Execution And Run Planning

节点执行器要求 `inputs.value` 中恰好有一个产物，并将其结构化克隆到 `nodeRun.outputs.preview`。`preview` 是不可连线的持久化运行结果，不在节点定义中暴露为输出端口；它让运行历史、最近成功投影、复用指纹和节点内预览继续使用现有 `CanvasNodeRun` 数据流。

在节点定义中声明被动预览终点语义，并让现有图片预览继续使用同一语义。运行目标包含某个上游节点时，运行规划递归纳入其直连被动预览终点；隔离运行规划也将其视为本地执行终点。新节点不增加付费能力或外部写入确认。

新节点沿用普通输入指纹复用规则：输入产物或节点定义变化时不复用，完全相同的持久化输入可复用。不要改变 `utility.image-preview` 已有的特殊复用兼容行为。

## UI And Data Flow

数据流如下：

```text
上游类型化输出 -> value:any -> 执行器快照 -> outputs.preview -> 节点内按 artifact.kind 展示
```

`CanvasFlowNode` 为新类型渲染 `CanvasDisplayAnyNodeResult`。组件遵循当前运行优先、最近成功结果回退的既有规则，并显示运行中、失败、阻塞、等待配置、取消、空结果、历史版本和复用状态。

展示分支复用现有交互：

- 文字显示截断摘要和全文预览按钮。
- 图片使用现有可横向浏览、可打开查看器的结果图库。
- 视频使用现有原生播放与大图层预览。
- 社交内容显示标题、媒体计数和“打开评审”入口。
- 发布任务显示任务 ID 与状态，不触发任何查询或写入。

节点使用 Lucide `Eye` 图标和现有工具节点视觉语言。新增样式只负责社交内容与发布任务的紧凑结果布局；节点缩放、移动端压缩、手势隔离、主题和无障碍沿用现有规则。

## Quick Add Compatibility

快速插入连接上下文改用 `CanvasPortKind`：

- 从任一类型化输出拖线时，`value:any` 是兼容候选并自动连接。
- 从 `value:any` 输入反向拖线时，所有已注册的类型化输出都是兼容候选。
- 单输入占用检查保持不变，第二条输入边必须被拒绝。
- 无连接上下文的节点搜索和分类不变。

## Compatibility And Rollback

节点类型和端口种类均为增量扩展；旧工作流不含 `any` 端口，仍按完全相同的类型规则解析。剪贴板协议版本、工作流 JSON、运行快照、API 和数据库结构不变。

回滚时可移除新节点定义、执行器、UI 分支及 `any` 输入兼容；旧工作流不受影响。已保存且包含新节点的工作流在回滚版本中会按现有未知节点规则明确拒绝，而不会静默改写。

## Verification Strategy

扩展 `canvas_workflows_check.mjs`，覆盖注册、端口方向、五类兼容、错误类型、单输入限制、剪贴板往返、被动纳入、执行结果、无付费能力和 UI 合同。模拟 Canvas API 的浏览器检查在 1440x960 和 390x844 下覆盖五类内容、当前/历史/失败状态、兼容快速插入、主题与水平溢出，不调用外部生产服务。
