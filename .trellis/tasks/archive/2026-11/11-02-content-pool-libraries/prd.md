# 内容池内容库/子集与标签管理

## Goal

让运营人员在「采集与内容池」工作台中像使用图库一样组织素材：创建内容库与子集、把条目批量归入多个库、用带颜色的自由标签整理和筛选，并让无限画布复用同一套库筛选。

## Background

- 内容池条目目前整体存放在 owner-scoped `content_projects.data_json`；`ContentProject` 是按采集关键词/批次自动生成的项目，不是可管理的库。
- 条目已有扁平 `customTags`，但没有库/子集、没有标签颜色、没有集中重命名/合并/删除能力。
- 图库 `/library` 已有成熟的库/子集树、多对多归属、批量加入/移动、标签建议与批量标签交互，可作为体验基准；但内容池与图库的数据领域必须保持独立。
- 内容池选择 API 与无限画布已经支持项目、平台、状态、媒体、内容分类和自定义标签筛选，但还没有库/子集维度。

## Requirements

- R1：内容池拥有独立的库/子集体系，不读写图库的 `library_collections` / `library_assets`。
- R2：用户可创建、重命名、移动、删除库和子集；删除库/子集时子节点上移，条目不删除。
- R3：条目可同时归属多个真实库/子集；支持批量加入、移动、从当前库移出、移回默认库。
- R4：默认库是隐式视图：没有任何归属的条目自动出现在默认库；加入其他库后自动离开默认库；移回默认库即清除全部归属。不做存量批量回填。
- R5：库视图支持“包含子集”开关；默认开启，可关闭以只看直属条目。
- R6：自定义标签支持颜色、重命名、合并、删除、批量添加/移除和筛选；标签管理只作用于 `customTags`，不改 AI 内容分类 `contentTagging.tags`。
- R7：标签继续沿用 NFKC 归一化、不区分大小写去重、每条最多 20 个、每个最多 40 个字符的限制。
- R8：关键词采集、链接导入、手工新增可选择目标库/子集；未指定时进入默认库（隐式）。
- R9：内容库/标签读写按 owner/admin 隔离；库归属只允许同 owner 条目。
- R10：`/api/content-pool/selection` 与无限画布内容池选择器/调度参数支持按库/子集筛选，并保持旧的已保存筛选兼容。
- R11：PostgreSQL 与 SQLite 双后端持久化；新表通过幂等 DDL 建表，不要求手工迁移存量条目。
- R12：内容台在桌面与移动视口下可用，不出现横向溢出或遮挡；保持现有采集、筛选、批量、二次创作流程。
- R13：不破坏现有快照、冻结、状态流转、简单运行、评审/发布链路。
- R14：默认验证不调用外部采集、模型、Feishu/Lark 或生产服务。

## Acceptance Criteria

- [ ] 可在 `/content` 左侧栏创建库、在其下创建子集、重命名、删除；删除后子集上移且条目仍在。
- [ ] 默认库显示所有未归属条目；条目加入真实库后从默认库消失；移回默认库后重新出现。
- [ ] 可多选条目一次性加入多个库/子集，或从当前库移动到目标库；其他库归属不被误删。
- [ ] 库视图的“包含子集”开关能正确切换直属条目与含后代条目。
- [ ] 标签可改色、重命名、合并、删除；重命名/合并/删除后条目上的 `customTags`、筛选结果和计数一致更新。
- [ ] 批量标签可一次添加或移除多个标签，并返回逐条失败明细。
- [ ] 关键词采集、链接导入、手工新增可指定目标库；未指定时条目出现在默认库。
- [ ] 内容台列表在“全部内容/默认库/任意库或子集”之间切换时，条目、计数、筛选、批量选择保持一致。
- [ ] 无限画布内容池选择器可按库/子集筛选，旧的保存筛选仍可打开并执行。
- [ ] 普通成员只能看到自己的库和条目；管理员维持现有全局可见规则。
- [ ] 旧内容池数据、旧 Canvas 工作流、简单运行和冻结快照无需迁移即可继续工作。
- [ ] `npx --no-install tsc --noEmit`、`npm run lint`、`npm run build` 和完整 Trellis 离线基线通过。
- [ ] 1440×900 与 390×844 的 mock 浏览器检查通过，无外部服务调用。

## Out Of Scope

- 库/子集的团队共享、角色权限或公开链接。
- 把内容池条目拆成独立数据库表或迁移媒体文件。
- 内容池项目的重命名/删除/归档。
- 智能文件夹、收藏、拖拽排序、缩略图管线。
- 内容池与图库之间共享或迁移素材。
- 修改 AI 内容分类枚举、提示词或历史打标结果。

## Technical Notes

- 条目仍以 `content_projects.data_json` 为事实来源；库/子集只存组织关系，标签注册表只存颜色/显示偏好。
- 归属与标签操作使用独立表和行级更新，避免每次整池重写。
- 默认库不建实体记录，由条目与归属关系计算。
- 详细设计见 `design.md`，执行顺序见 `implement.md`。
