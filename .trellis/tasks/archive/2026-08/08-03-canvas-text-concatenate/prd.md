# 无限画布文本拼接节点与生产发布

## Goal

在 FluxPost Studio 的无限画布中新增一个可组合的“文本拼接”节点，让操作者可以把多路文本按指定分隔符合并为一路文本，并在本地验证通过后以可追溯的固定 Git SHA 推送到 GitHub、部署到生产环境。

## Background

- 用户提供的参考节点为 WAS Node Suite 的 `Text Concatenate`：四个文本输入 `text_a`、`text_b`、`text_c`、`text_d`，一个 `delimiter` 文本配置，一个 `clean_whitespace` 布尔配置，以及一个字符串输出。
- 当前无限画布已经具备类型化文本端口、节点注册表、节点执行器、配置面板、工作流持久化、快速添加、运行记录和确定性 Canvas 基线检查。
- 当前生产环境运行固定 SHA `a65767384c1b1993c95c8c32d053edcd10c3fac6`；发布必须沿用项目已有的固定 SHA 部署与验证流程。
- 当前本地发布分支 `release/production-20260803` 比远端多 3 个已有提交；存在与本任务无关的未跟踪截图，实施和提交不得改动或包含这些文件。

## Requirements

### R1 节点目录与端口

- 无限画布节点库和快速添加搜索中提供新的实用工具节点“文本拼接”。
- 节点提供四个有序文本输入，稳定内部端口 ID 为 `text_a`、`text_b`、`text_c`、`text_d`。
- 四个端口在界面显示为“文本 A”“文本 B”“文本 C”“文本 D”；配置在界面显示为“分隔符”和“清理首尾空白”。
- 节点提供一个文本输出，能够连接到现有所有接受 `text` 类型的下游端口。
- 节点可保存、重新加载、复制，并遵守现有节点版本、大小、执行模式和图校验规则。

### R2 拼接配置与执行

- 节点提供 `delimiter` 文本配置，支持使用换行符作为分隔符。
- 节点提供 `clean_whitespace` 布尔配置。
- 执行时按端口顺序拼接输入，结果作为标准 Canvas `text` artifact 输出。
- 四个文本输入均为可选，执行时仅处理实际连接并产生文本 artifact 的输入。
- 按 `text_a`、`text_b`、`text_c`、`text_d` 的固定顺序处理输入。
- `delimiter` 为实际换行或字面量 `\\n` 时都使用单个换行符拼接。
- `clean_whitespace=true` 时先清理每路输入的首尾空白；关闭时保留原始空白。
- 忽略空字符串；关闭空白清理时，仅含空白的字符串仍视为有效输入。
- 没有有效输入时仍成功输出空文本。
- 节点为本地纯文本处理，不调用模型、付费服务或外部写入服务。

### R3 验证

- 为节点定义、端口、默认配置、配置校验和执行语义增加确定性自动化覆盖。
- 更新现有 Canvas 静态基线，使新节点进入已支持节点集合。
- 执行 `.trellis/spec/fluxpost/verification.md` 规定的基线命令，并在需要时运行前端构建、本地生产重启和 Canvas 页面人工/浏览器检查。
- 默认验证不得调用任何外部生产服务，也不得修改用户运行数据。

### R4 GitHub 与生产发布

- 只提交本任务相关代码、测试和必要 Trellis 状态，不纳入本地运行数据、秘密、环境文件、生成媒体、调试产物或无关截图。
- 推送完成验证的提交到当前 GitHub 发布分支。
- 使用项目已确认的部署入口，将精确提交 SHA 部署到生产环境；部署前执行现有的活动任务/数据保护门禁和数据库备份步骤。
- 部署后确认运行 release、镜像和应用对应预期 SHA，并完成现有 HTTP、认证边界、服务健康与数据卷保留检查，不触发付费 provider 或外部写入。

## Acceptance Criteria

- [x] AC1：操作者能在无限画布节点库和快速搜索中找到并创建“文本拼接”节点，看到四个有序文本输入、分隔符、空白清理开关和一个文本输出。
- [x] AC2：节点按最终确认语义正确处理四路输入、缺省/空输入、普通分隔符、换行分隔符和 `clean_whitespace` 的开/关状态。
- [x] AC3：输出使用标准 `text` artifact，可连接现有文本下游节点；工作流保存、加载、复制、图校验和运行记录保持正常。
- [x] AC4：新增的聚焦自动化、TypeScript、lint、production build 和项目全量基线全部通过，且没有调用外部生产服务。
- [x] AC5：本地生产服务器刷新后，桌面和移动端 Canvas 页面无布局溢出或节点控件遮挡，核心创建/配置/连线/运行流程可用。
- [x] AC6：GitHub 发布分支包含经验证的精确提交 SHA，且没有秘密、运行数据、生成媒体、调试产物或无关文件。
- [x] AC7：生产环境部署并验证同一精确 SHA，应用、PostgreSQL、Nginx/HTTPS、认证边界、后台 worker、必要 schema 和持久化 volumes 均通过现有部署检查，可明确回滚到部署前 release。

## Out Of Scope

- 动态增加超过四个输入端口。
- 富文本、Markdown 语法转换、模板变量替换或多类型 artifact 自动转文本。
- 调用 GPT、ComfyUI、Seedance、TikHub、Feishu 或其他外部服务。
- 清理当前分支已有提交、无关未跟踪截图或生产历史 release。
