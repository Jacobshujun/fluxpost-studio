# 批量原创小红书图文工作台

## Goal

新增独立 `/original` 工作台，使运营人员一次录入最多 100 组选题，并在提交后自动完成策划、标题、正文、2-10 张小红书卡片及生成后质量校验。结果统一进入现有审查台，不自动写入飞书。

## Background

- 现有首页原创模式每次生成一篇内容和最多 5 张相互独立的图片，必须保持兼容。
- 新工作台采用 `baoyu-xhs-images` v2.0.1、提交 `6b7a2e417500561a5ecdd0b168332f4142584617` 的方法论，不依赖其运行时。
- 上游代码为 MIT License；移植规则时保留版权、许可与来源声明。
- 内容定位为汽车优先、通用选题兼容；通用选题不强制写入飞书车型字段。

## Requirements

- 独立页面支持可编辑行和 TSV 粘贴，列为选题、要求、可选车型/关键词；空行忽略，重复行提示但允许提交。
- 服务端原子校验 1-100 行：选题 1-120 字、要求最多 4000 字、车型/关键词最多 96 字。
- 批次设置支持自动或指定的策略、风格、布局、配色和 2-10 张图片；联网检索为批次开关且默认关闭。
- 提交前展示项目数、图片请求上限、实际画幅和供应商配置；启动后不设置中途人工门槛。
- 每个项目先生成内容策划和卡片大纲，再生成标题、正文、标签和精确逐页文案。
- 使用 12 种风格、8 种布局、3 套配色和版本化 Prompt 组装规则；首图无参考生成，后续图片以首图作为唯一风格锚点。
- 优先使用 3:4；仅支持标准 OpenAI JSON 尺寸时明确使用 1024x1536 的 2:3 兼容比例，不裁切。
- 每张图片通过视觉模型检查文字、乱码、层级、安全区和一致性；失败自动重试一次，之后进入待审查并保留候选图。
- 标题正文成功但部分图片失败时保存部分草稿；策划或文案失败只影响当前批次项。
- 批次、批次项、队列在 SQLite/PostgreSQL 中持久化，支持 owner/admin 隔离、重启恢复、暂停、继续、取消及仅重试失败项。
- 生成稿保存批次来源和结构化卡片系列，同时保持 `imageUrls`、现有审查台和飞书附件发布兼容。
- 默认不自动写入飞书；生成稿必须经过现有审查台人工批准。

## Acceptance Criteria

- [ ] `/original` 可录入或粘贴最多 100 行，逐行显示确定性校验与重复提示。
- [ ] 一次 API 请求要么完整创建有效批次和全部项目，要么不写入任何批次数据。
- [ ] Mock 生成验证封面先完成，所有后续卡片引用同一封面，单卡 QA 最多触发一次自动重试。
- [ ] 批次暂停后不领取新项目，取消后不发起新供应商请求，继续和失败重试不会重复生成成功帖子。
- [ ] 部分图片失败仍产生可审查的标准生成稿，并在审查台显示系列元数据和 QA 问题。
- [ ] 未登录和跨 owner API 访问被拒绝；管理员仍能读取与操作团队批次。
- [ ] 现有单篇原创保持每次一篇、最多 5 图及原有发布行为。
- [ ] 确定性检查、TypeScript、变更文件 lint、生产构建和可用 Trellis 基线通过；默认检查不调用付费服务。
- [ ] 本地生产服务器刷新后，桌面与移动端工作台无横向溢出或控件重叠。

## Out Of Scope

- 单选题多版本、CSV/XLSX 文件上传、三套大纲人工选择。
- 模板排版渲染、参考图、水印和自动写入飞书。
- 运行时安装或调用外部 `baoyu-xhs-images` Skill。
