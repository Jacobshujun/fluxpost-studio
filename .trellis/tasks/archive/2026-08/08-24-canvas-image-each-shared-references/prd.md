# 逐图 GPT 重构共享参考图

## Goal

让无限画布的“逐图 GPT 重构”节点在依次处理一组原图时，为每一次 GPT-Image-2 请求附加同一组单张或多张共享参考图，支持统一车辆、主体或视觉特征，同时保留没有共享参考图时的现有行为。

## Background

- 当前 `model.gpt-image-each@1` 将 1–18 张待处理图片拆成独立子任务，每次只提交当前原图并请求一个输出。
- GPT-Image-2 Canvas 调用已经支持最多 16 张有序参考图和异步 provider task 恢复。
- 用户确认每次请求应采用 `[当前原图, ...共享参考图]`；共享参考图通过独立画布端口提供；节点不得自动改写用户提示词。

## Requirements

- 新版节点必须提供必填的“待重构图片组”、可选且支持多连线的“共享参考图”以及必填的“共享提示词”输入端口。
- 每张待重构图仍独立调用一次 GPT-Image-2，固定 `count=1`，且请求图片顺序必须为当前原图在首位、共享参考图随后。
- 待重构图片最多 18 张；共享参考图按输入顺序去重后最多 15 张；若共享图与当前原图重复，首位原图保留、后续重复项移除。
- 节点必须原样提交用户提示词，不自动增加图片角色、车辆或风格说明。
- 输出只包含按原图顺序聚合的生成图片及处理报告；共享参考图不得混入输出。
- 共享参考图必须参与运行指纹、失败重试和 provider 恢复契约。改变共享参考图后不得复用旧子任务结果。
- 运行详情必须显示共享参考图数量和每次请求的参考图数量，并保留现有成功、处理中、失败与失败序号信息。
- V1 历史定义和运行必须可读；保存或导入的 V1 工作流升级到 V2 后不得改变无共享参考图时的结果。
- 跳过模式只透传待重构图片组；普通 Canvas、旧批量调度和灵活调度继续支持该节点作为图片目标。
- 离线验证不得调用真实 GPT-Image-2、Feishu 或其他外部付费服务。

## Acceptance Criteria

- [ ] V2 节点暴露 `images`、`references`、`prompt` 三个输入端口，其中 `references` 可空并支持多个图片来源。
- [ ] 对 N 张原图和 M 张共享参考图，产生 N 次请求；每次 `count=1`，参考图为当前原图在前、相同的有序共享参考图在后。
- [ ] 无共享参考图时，每次请求仍只包含当前原图，输出、重试和恢复行为与 V1 一致。
- [ ] 共享参考图去重、与当前原图去重、15 张边界及超限前置阻断均有确定性检查。
- [ ] 更改共享参考图使旧子任务失效；同一输入的部分失败只重试失败子任务；pending 子任务继续按原 provider task id 恢复。
- [ ] 成功结果按原图顺序聚合，部分失败、报告、评审草稿与发布阻断契约不回归。
- [ ] V1 图迁移、V1 历史运行读取、V2 图校验、跳过模式及调度器兼容通过离线检查。
- [ ] 节点及运行详情可见共享参考数量与每次实际参考数量，不增加节点内上传或自动提示词。
- [ ] focused check、TypeScript、lint、build 和完整 Trellis baseline 全部通过。

## Out Of Scope

- 节点内直接上传或粘贴共享参考图。
- 参考图权重、遮罩、逐原图配对、动态角色标签或自动提示词。
- 数据库迁移、真实付费 provider 验证、推送或生产部署。
