# Canvas 主任务共享上游结果

## Goal

为无限画布批量调度 V2 增加显式的主任务共享输出，使只依赖主任务参数的上游节点每个主任务执行一次，并把冻结结果复用到该主任务的全部子任务。目标场景必须从三次重复视觉分析变为一次视觉分析加三次图片生成。

## Background

- 当前 V2 为每个子任务克隆完整画布并执行到子任务结果节点，因此主任务参数虽然广播，相关上游模型仍会在每个子任务中重复执行。
- Canvas artifact 已支持持久化 `text`、`images` 和 `videos`，调度器已有主任务、子任务、聚合阶段及 durable Canvas run/queue。
- 共享行为必须是具体 schedule 的显式选择，不能改变普通画布运行，也不能变成跨主任务或跨任务的全局缓存。

## Requirements

- R1：V2 definition 支持多个共享输出；每项使用稳定的 `nodeId + outputPort + artifactKind`，默认空列表保持现有行为。
- R2：共享节点必须只有一个 `text`、`images` 或 `videos` 输出，严格位于子任务结果节点上游，且其祖先闭包不得包含任何子任务参数绑定。
- R3：输入节点、被动展示节点、多输出节点、外部写入节点及非支持 artifact 节点不得共享；无效定义必须在 provider 调用前失败。
- R4：每个主任务把全部共享目标合并为一个 shared Canvas run。成功后冻结选择端口的 artifact，并用 literal 节点替换子任务图中的共享节点，再原子创建该主任务全部子运行。
- R5：共享失败时不启动对应子任务；只允许重试失败共享阶段。成功共享结果不可在原任务内重跑，子任务重试继续使用相同冻结结果。
- R6：暂停、恢复、取消、进程恢复、状态聚合及 run-id 收集覆盖 shared phase；现有 child 与 aggregate phase 行为保持兼容。
- R7：旧 V1/V2 记录继续读取；保持 `schemaVersion: 2` 和 JSON/JSONB 持久化，不增加数据库迁移。
- R8：批量调度 UI 支持多选共享输出，并在预演/运行树显示每主任务共享阶段、结果、错误和失败重试。
- R9：默认验证不得调用真实文本、图片、视频 provider 或外部写入服务。

## Acceptance Criteria

- [ ] 一张主任务美图、一个共享 GPT 视觉节点和三张子任务图片产生一个 shared run 与三个 child run；视觉节点只执行一次，图片节点执行三次。
- [ ] 多个独立或有上下游关系的共享节点能在同一个 shared run 中冻结，并正确替换/重连每个子任务图。
- [ ] 子任务依赖、重复输出、非上游节点、多输出节点、不支持 artifact、被动节点和外部写入在预演阶段明确失败。
- [ ] 共享失败、失败重试、暂停/恢复、取消、进程恢复、子任务重试和聚合均有确定性覆盖。
- [ ] 未配置共享输出的 V2 调度及历史 V1/V2 数据行为不变。
- [ ] API/UI 能配置和查看共享阶段，且不允许成功共享结果级联重跑。
- [ ] Canvas 专项检查、TypeScript、lint、build、完整 Trellis baseline、本地生产重启与 HTTP smoke 通过。

## Out Of Scope

- 跨主任务、跨 schedule 或跨工作流缓存。
- 成功共享结果的级联重跑及已生成草稿作废。
- 多输出节点的部分端口共享、`socialPost` 或 `publishJobRef` 共享。
- 自动推断并默认启用共享。
