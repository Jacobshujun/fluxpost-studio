# Seedance reference mentions

## Goal

让无限画布的 Seedance 2.5 节点在接收多张参考图片时，提供类似官方平台的 `@` 图片提及体验，使用户可以在 Prompt 中明确指定人物、车辆、产品或场景所对应的参考图片，并在图片调整后继续保持引用关系明确、可验证和可复现。

## Background

- 当前 `model.seedance` 接收一个可多连的 `images` 端口，执行器将所有图片压平为 URL 数组后按数组顺序发送给 Ark。
- 当前图片 artifact 只有 URL 和可选名称；Seedance 节点没有图片引用 ID、别名或 Prompt 提及映射。
- 当前运行输入按照画布 `edges` 的保存顺序聚合。只使用 `@图片1` 等位置文本会在重新连线、重排或删除图片后产生错误指向。
- Ark quickstart 的 API 示例使用“图片1”“视频1”这类自然语言序号，并将对应媒体按相同顺序放入 content；`@` 是编辑器选择交互，不应作为未经证明的 API 控制符原样发送。
- Seedance 当前最多接受 9 张图片，且参考素材必须是 Ark 可访问的 HTTP(S) URL。

## Requirements

- R1. Seedance Prompt 编辑区域在用户输入 `@` 时显示当前可用参考图菜单，菜单包含缩略图、序号和用户可读名称。
- R1a. Seedance 节点同时支持在属性区直接上传参考图片和通过 `images` 端口连接上游图片节点；两类来源统一进入同一个可提及引用集合，并按稳定规则去重和排序。
- R1b. Seedance 节点属性区提供专用 Prompt 编辑器；节点内 Prompt 为空时兼容使用上游文字输入，节点内 Prompt 与上游文字同时非空时运行前报错，不自动拼接或静默选择。
- R2. 用户选择参考图后插入结构化提及；提及必须绑定稳定引用身份，不能仅依赖当前数组位置。
- R2a. 提及名称严格采用官方固定图片序号，不提供自定义别名。界面中的序号随最终参考图顺序自动更新，但结构化提及仍绑定原图片身份。
- R2b. `@` 菜单只包含运行前可确定的固定图片：Seedance 节点内上传、普通图片输入和图库快照。动态模型输出可继续作为未提及的普通参考图传入，但不得绑定结构化提及；用户需要提及时必须先将结果冻结为固定图片输入。
- R3. 系统允许同一 Prompt 提及多张图片，并在提交前将界面中的 `@图片N` 结构化提及确定性序列化为 quickstart 已证明的“图片N”文本，同时以完全一致的顺序构造 `content` 图片项。
- R4. 图片重排不得改变已有提及所指向的图片；删除已提及图片后必须在运行前显示明确错误，不得静默改绑到另一张图片。
- R5. 节点运行快照必须保存原始 Prompt、解析后的提交 Prompt、引用身份与最终图片顺序，使历史任务可解释且重试不会改变绑定。
- R6. 未使用 `@` 的现有 Seedance 工作流继续按当前多图行为运行；保存的 `model.seedance` version 1 图仍可读取。
- R7. 输入继续遵守最多 9 张图片、公共 HTTP(S) URL、Prompt 长度和现有合规校验。
- R7a. Seedance 节点内直接上传必须要求 TOS 已启用且配置完整；上传成功后必须得到公共 HTTP(S) URL，否则不写入节点配置并返回明确的配置错误。上游本地 URL 在运行前明确拒绝。
- R8. 默认验证使用 mock，不调用付费 Ark 服务；请求序列化以用户提供 quickstart 中“图片N”文本与有序 content 的契约为依据。

## Acceptance Criteria

- [ ] AC1. 多张参考图可在 Seedance Prompt 编辑器的 `@` 菜单中通过缩略图和名称区分，选择后形成可见提及。
- [ ] AC1a. 节点内直接上传和上游连接的图片可以同时参与一次 Seedance 请求，重复 URL 只形成一个引用项，合计仍不得超过 9 张。
- [ ] AC1b. 新节点可直接编辑 Prompt 并插入图片提及；旧节点仍可由上游文字驱动，两种 Prompt 来源冲突时显示可操作的校验错误。
- [ ] AC2. 两张或以上图片交换显示顺序后，已有提及仍解析到原图片；删除被提及图片时运行前校验失败并指出失效提及。
- [ ] AC2a. 动态上游图片结果不出现在 `@` 菜单中，也不会被错误保存为稳定提及；固定上游快照可被选择并在重载工作流后保持绑定。
- [ ] AC3. Mock Ark 创建请求证明编辑器中的 `@图片N` 被序列化为“图片N”，且文本序号和 `reference_image` content 顺序严格一致。
- [ ] AC4. Canvas node run 保存足够的解析输入信息，可展示一次执行实际使用的 Prompt 与图片绑定，并确保同一 pending Ark task 恢复时不重新解析或重新提交。
- [ ] AC5. 不含结构化提及的历史 Seedance 节点可加载并执行，其他画布图片消费者不受影响。
- [ ] AC6. 画布聚焦检查、TypeScript、lint、build 与 Trellis 离线基线通过，且验证过程没有真实付费 Seedance 调用。
- [ ] AC7. TOS 未配置、上传未返回公共 URL 或上游引用为本地 URL 时均在 Ark POST 前失败，且错误不包含密钥或本地敏感路径。

## Out Of Scope

- 不承诺模型生成结果中的人物或产品达到像素级身份一致；`@` 提及只保证请求引用明确。
- 不在本任务中训练主体 LoRA、创建角色资产库或增加视频内局部蒙版编辑。
- 不为参考视频增加 `@视频N` 选择器；现有视频输入与“视频N”手写 Prompt 行为保持不变。
- 不默认执行真实付费生成；真实 Endpoint 冒烟测试需要用户单独授权。
