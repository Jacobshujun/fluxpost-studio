# 批量调度结果直接下载图片

## Goal

让用户在批量调度结果中直接下载每个主任务已聚合的图片，无需先打开任务中心、选中对应运行、返回画布再寻找“保存图片”节点。

## Background

- 2026-08-17 本地诊断确认“test 批量任务”成功产生 10 张图片，3 个主任务的 `utility.save-images` 结果分别包含 3、4、3 张。
- 批量面板轮询只更新调度状态，不会选中主任务运行；现有下载按钮只渲染在画布的“保存图片”节点内（`src/app/canvas/page.tsx:1622`）。
- 现有鉴权下载路由、文件名规则和串行浏览器下载逻辑已经可用，应复用而不是新增存储路径。

## Requirements

- 灵活调度 V2 的运行结果中，每个状态为“已完成”或“部分完成”且存在主运行 ID 的主任务必须提供直接下载入口。
- 点击入口后，系统必须从该主运行的最新节点尝试中找到已成功的 `utility.save-images` 结果，并复用现有逐张浏览器下载逻辑。
- 一个主运行如果包含多个成功的“保存图片”节点，入口必须按节点结果顺序下载全部图片。
- 下载期间必须防止重复触发，完成后展示成功和失败数；没有可下载结果时显示明确错误。
- 保持现有的手动用户操作边界，不在调度完成时自动触发浏览器下载。

## Acceptance Criteria

- [x] 完成或部分完成的 V2 主任务可在批量调度结果内直接点击“下载图片”。
- [x] 入口不依赖当前画布选中的运行，能按主任务的 `mainRunId` 下载其实际保存图片结果。
- [x] 多张和多保存节点结果串行下载，单张失败不阻断后续图片，界面报告成功/失败计数。
- [x] 进行中、尚未产生主运行的主任务不显示可用下载按钮。
- [x] 现有画布节点内“下载全部”行为保持不变。
- [x] Canvas 相关确定性检查、TypeScript 和 lint 通过。

## Out Of Scope

- 自动下载、ZIP 打包、服务器指定目录或新的永久媒体副本。
- 重构批量调度执行、聚合或数据库模型。
- 向历史 V1 调度界面增加同类入口。
