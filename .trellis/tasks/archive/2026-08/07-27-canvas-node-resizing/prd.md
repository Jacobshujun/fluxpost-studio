# 画布节点自由缩放

## Goal

让桌面端画布操作员像使用 ComfyUI 一样，直接拖拽选中节点的边或角调整节点宽高，以便为长文本、图片和结果预览分配合适空间；尺寸应成为工作流的一部分并可靠保留。

## Background

- `/canvas` 使用 `@xyflow/react@12.11.2`，依赖已提供 `NodeResizer`，无需引入新库。
- `src/app/globals.css:213` 当前把所有 `.canvas-node` 固定为 `220px` 宽，移动端另固定为 `190px`。
- `CanvasNode` 当前只持久化 `position`，`currentGraph` 也只从 React Flow 节点回写坐标。
- 工作流图以 JSON 存入现有 SQLite/PostgreSQL `canvas_workflows` 记录；增加可选节点尺寸不需要数据库迁移。
- 复制、剪切、粘贴和工作流运行快照都复用 `CanvasNode`，因此尺寸契约必须在共享类型、图校验和剪贴板解析中显式支持。

## Requirements

- R1. 可编辑桌面画布中，选中节点时显示清晰但克制的四边和四角缩放控件。
- R2. 用户可独立调整宽度和高度，不强制锁定宽高比。
- R3. 所有当前及后续注册的节点类型统一支持缩放，不维护按节点类型区分的例外清单。
- R4. 节点尺寸必须限制在可用范围内，防止端口、标题、菜单和正文控件重叠或节点覆盖整个工作区。范围为：宽 `190-720px`，高 `120-900px`。
- R5. 未自定义尺寸的旧工作流继续采用当前默认宽度和内容驱动高度，不产生迁移或视觉回归。
- R6. 自定义尺寸通过现有工作流 JSON 自动保存，刷新、切换工作流、复制工作流和运行快照后保留。
- R7. 复制、剪切、粘贴和创建节点副本保留每个节点的自定义尺寸；外部剪贴板载荷中的尺寸必须经过有限数值校验。
- R8. 节点内部的文本编辑、图片预览、视频和结果区域应利用可用宽度；高度不足时内容区域内部滚动，不能溢出或遮挡端口。
- R9. 移动端继续保持结构只读/检查模式，不显示或响应缩放控件。
- R10. 缩放只改变画布布局，不改变节点配置、端口契约、执行计划、模型调用或发布行为。

## Acceptance Criteria

- [x] AC1. 在宽屏桌面选中节点后，可从任一边或角拖拽到任意非锁定宽高比例，拖动期间节点和连线实时更新。
- [x] AC2. 节点无法缩小到低于 `190x120`，也无法放大到超过 `720x900`。
- [x] AC3. 保存并重新加载工作流后，自定义尺寸与缩放导致的位置变化一致保留；旧节点没有尺寸字段时仍按当前默认外观渲染。
- [x] AC4. 复制粘贴、剪切粘贴、节点副本和工作流副本均保留尺寸；非法、非有限或越界尺寸被拒绝。
- [x] AC5. 文字节点、图片节点、结果画廊、视频结果及端口在最小、默认和最大尺寸下不发生不可读重叠，必要时内部滚动。
- [x] AC6. `<=820px` 移动布局不显示缩放控件，也不能通过 React Flow 尺寸变更修改节点。
- [ ] AC7. 画布专项检查、TypeScript、lint、build、完整 Trellis 基线、本地生产重启和模拟桌面/移动浏览器检查通过，且不调用付费或外部生产服务。

## Out Of Scope

- 多节点等比批量缩放、自动布局、对齐/分布命令和尺寸预设工具栏。
- 用缩放改变画布整体 zoom、媒体原始分辨率或模型生成尺寸。
- 数据库表迁移、Canvas API 路由形状变化或节点版本升级。
