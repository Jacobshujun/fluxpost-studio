# 修复 Canvas 自动与手动保存竞争

## Goal

修复 `/canvas` 自动保存与手动保存竞争，确保用户连续编辑、自动保存进行中点击保存、运行前保存等场景不会静默丢弃保存意图，并能明确看到最新编辑是否已持久化。

## Background

- 画布编辑后 900ms 自动保存，自动与手动保存共用 `busy`。
- 当前 `saveWorkflow` 在 `busy` 时直接返回 `false`，工具栏按钮也被禁用；用户只看到图标闪烁，没有成功或失败的可靠反馈。
- PostgreSQL 最近工作流 revision 正常递增、列与 JSON 一致且无数据库锁，故修复限定在前端保存协调与验证。

## Requirements

- 同一时间最多发送一个工作流 PATCH，后续保存意图必须合并并在前一请求完成后使用最新图、名称和 revision 再保存。
- 手动保存必须取消尚未启动的自动保存，并等待/触发最新编辑持久化；不得因自动保存正在执行而静默返回。
- 保存完成只能清除已被该请求覆盖的 dirty 版本；请求中发生的新编辑必须继续保持 dirty 并排队保存。
- 工作流切换后，旧工作流保存结果不得覆盖当前工作流状态。
- HTTP 409 和其他错误必须保留 dirty，并显示明确错误；不得无限重试。
- 保存按钮展示稳定的“保存中”和“已保存”反馈，且不因无关全局 busy 短暂闪烁。
- 不改变服务端 revision 乐观锁、工作流 API、数据库 schema 或 900ms 自动保存策略。

## Acceptance Criteria

- [x] 慢自动保存期间继续编辑会串行发送第二次 PATCH，第二次使用第一次响应 revision 和最新图。
- [x] 自动保存等待期点击手动保存只发送一次最新 PATCH，并明确显示保存完成。
- [x] 保存进行中点击手动保存不会丢弃意图，也不会并发发送相同 revision。
- [x] 409/失败保留 dirty 和错误信息，随后由用户再次保存，不产生自动重试循环。
- [x] 现有 Canvas 工作流检查、竞态浏览器检查、TypeScript、lint、build 和完整 Trellis baseline 通过。
- [x] 提交后用 `npm run local` 激活，端口 3001 `/api/version` 与最终 clean HEAD 一致且 `/canvas` 返回 200。

## Out Of Scope

- 自动合并跨标签页冲突、离线保存、服务端 API/schema 变更或移除自动保存。
