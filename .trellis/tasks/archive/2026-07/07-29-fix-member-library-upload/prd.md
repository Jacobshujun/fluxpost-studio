# 修复普通成员图库上传

## Goal

修复已登录普通成员无法向参考图库或车型图库上传图片的问题，使成员能够创建并维护归属于自己的图库资产，同时保持现有所有者/管理员编辑权限边界。

## Background

- 用户确认普通成员当前无法上传图片到图库。
- 普通成员执行上传后界面没有显示任何成功、失败或错误提示。
- 问题账号 `xiawanzhen` 在本地数据库中是启用的 `operator`，会话有效且今天仍被服务端刷新，名下尚无图库资产。
- 现有产品规则要求已登录成员可以导入自己的资产；团队共享资产仍仅所有者或管理员可编辑。
- `POST /api/library/import` 当前要求登录，并将当前账号传入 `importLibraryAsset`。
- `importLibraryAsset` 的静态实现默认使用当前账号作为资产所有者，代码中没有显式的管理员上传限制。
- `src/app/library/page.tsx` 在创建上传队列时直接调用浏览器 `crypto.randomUUID()`，且调用发生在任何上传状态或错误处理之前；该 API 在局域网 HTTP 等非安全上下文中可能不可用，异常会造成选择图片后无记录、无提示。
- 浏览器隔离检查确认空图库按钮、文件选择器、上传请求和成功状态在具有 UUID API 时均可工作，因此修复范围是客户端队列 ID 与同步异常反馈，而不是放宽服务端权限。
- 现有确定性检查验证了鉴权、所有者/管理员编辑权限和一般导入合同，但没有以 `role: "operator"` 覆盖完整的导入权限回归。

## Requirements

- R1: 已登录且状态有效的普通成员可以向参考图库和车型图库上传受支持的图片。
- R2: 普通成员上传的新资产必须归属于当前成员，且成员可以继续编辑、打标签、调整可见性和删除自己的资产。
- R3: 不放宽团队共享资产的权限；普通成员仍不能修改或删除其他用户的资产，也不能把图片导入其他用户的集合。
- R4: 未登录请求仍返回鉴权失败；文件类型、30 MB 上限、TOS 配置、去重和参考图自动打标规则保持不变。
- R5: 增加不调用外部 TOS、GPT 或其他生产服务的确定性回归，明确覆盖普通成员上传路径。
- R6: 导入失败时应保留足够明确的服务端错误分类和用户可见信息，以便区分鉴权失败、输入错误与存储/持久化故障。
- R7: 客户端上传队列不得依赖仅在安全上下文可用的浏览器 API；局域网 HTTP、localhost 和 HTTPS 下都必须能创建稳定且足够唯一的临时队列 ID。

## Acceptance Criteria

- [ ] AC1: 隔离测试中的 `operator` 账号可成功导入参考图和车型图，返回资产的 `ownerUserId` 等于该账号 ID，且 `canEdit` 为 `true`。（R1, R2, R5）
- [ ] AC2: 普通成员不能通过导入参数指定其他所有者，也不能向其他用户的集合写入资产。（R2, R3）
- [ ] AC3: 其他用户的团队共享资产对普通成员保持只读，现有管理员行为不回归。（R3）
- [ ] AC4: 未登录、无效图片、超限图片和未配置 TOS 的行为保持明确且可区分；默认验证不调用外部服务。（R4, R5, R6）
- [ ] AC5: 相关定向检查、TypeScript/构建检查及 FluxPost Trellis 基线通过。（R5）
- [ ] AC6: 在 `crypto.randomUUID` 不可用或抛错的模拟环境中，选择图片仍会创建上传记录并发出导入请求；同步客户端错误不会再静默丢失。（R6, R7）

## Out Of Scope

- 修改图库共享或所有权模型。
- 允许普通成员维护其他用户的集合或资产。
- 修改 TOS 凭据、生产配置或历史图库数据。
- 重新设计图库上传界面或新增图片格式。
