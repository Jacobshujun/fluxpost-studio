# 文案库与画布批量二创

## Goal

为 FluxPost Studio 增加一个可人工维护、可复用的文案库。每篇文案由标题、正文和人工标签组成；文案既能在独立库页面中管理，也能作为无限画布的输入，经 GPT 等文本模型二次创作后由内容组装节点生成待审查内容，并能进入现有批量调度流程。

## Background

- 用户明确要求参考现有图片库搭建文案库。
- 用户明确要求文案由用户手动录入，包含“标题”和“正文”两部分，并支持手动标签。
- 用户明确要求无限画布新增可引用文案的节点，允许接入 GPT 等文本模型进行二次创作。
- 用户明确要求二创结果继续通过现有内容组装节点生成待审查内容。
- 用户明确要求同一能力进入现有批量调度模块。
- 当前画布已经提供 GPT 文本、文本拆分和内容组装节点；批量调度已经有最终内容运行阶段，应复用这些执行边界。

## Requirements

### R1 文案持久化与权限

- 文案记录必须持久化在现有运行数据库中，同时支持 PostgreSQL 和 SQLite 回退路径。
- 每条文案至少包含稳定 id、标题、正文、人工标签、所有者、创建时间和更新时间。
- 文案支持“仅自己 / 团队共享”可见性，创建时默认“仅自己”。
- 普通成员可以读取自己的文案和其他成员主动共享的文案，只能修改或删除自己的文案；管理员沿用现有工作区规则，可访问并管理全部所有者的数据。
- 标题和正文由用户手动录入；标签为用户维护的自由文本标签，不触发 AI 自动打标。

### R2 文案库页面

- 增加可从现有应用导航进入的文案库工作区。
- 用户可以创建、查看、搜索或筛选、编辑和删除文案。
- 创建与编辑表单明确分离标题、正文和标签，并显示保存、失败、空状态和删除确认反馈。
- 页面延续图片库的紧凑工作台风格，但针对长文本阅读与编辑设计，不照搬图片预览交互。

### R3 文案库 API

- 提供经工作区登录保护的文案列表、创建、更新和删除接口。
- API 在入口验证标题、正文、标签和 id，返回稳定的 JSON 契约与明确 HTTP 状态。
- 所有读取和写入均由服务层执行账号范围过滤，页面组件不直接处理数据库结构。

### R4 无限画布文案引用节点

- 新增一个“文案库”输入节点，允许用户从自己可访问的文案中选择一篇。
- 节点持久化所选文案的稳定引用与运行所需快照，至少输出独立的标题和正文文本端口。
- 画布保存或运行不因文案库原记录随后被编辑或删除而静默改变；用户重新选择或显式刷新时才更新快照。
- 标题、正文输出可分别接入 GPT 文本节点、文本处理节点和现有内容组装节点。
- 画布节点选择器、节点摘要、检查器和执行器均使用同一共享类型契约。

### R5 文本二次创作与待审查内容

- 现有 GPT 文本节点继续负责模型调用；文案库节点本身只负责确定性输入，不直接调用模型。
- 用户可以分别或组合标题、正文进行二次创作，并将最终标题、正文连接到现有内容组装节点。
- 标准批量调度骨架默认使用两个独立 GPT 文本节点分别改写标题和正文，以便配置不同指令并保持输出端口确定；每篇内容默认产生两次文本模型调用。
- 内容组装沿用现有 GeneratedPost/评审工作区路径，不新增平行的待审查存储。

### R6 批量调度集成

- 批量调度能够为批次内容任务提供文案库输入，并在不可变运行图中冻结每个任务使用的文案快照。
- 每个批次提供文案池配置：既可手动选择多篇文案，也可按人工标签筛选文案。
- 预览时将筛选结果按稳定顺序循环分配给内容任务；相同批次配置和库快照必须产生相同分配结果。
- 文案输入与现有场景图片、车型图片、提示词策略、图片目标和内容目标绑定规则兼容。
- 调度预检必须在启动付费模型调用前识别文案选择为空、绑定节点错误或所需快照缺失。
- 批量最终内容仍由现有内容目标节点组装为一条待审查内容。

### R7 兼容与质量

- 现有工作流、已保存画布、图片库和无文案输入的批量调度保持兼容。
- 默认自动验证不得调用真实 GPT、图片模型、TOS 或飞书写入。
- 新增确定性检查覆盖数据库契约、账号隔离、API/节点注册、快照执行和批量调度图注入。
- 前端完成后验证桌面与移动端无溢出、遮挡或不可操作控件。

## Acceptance Criteria

- [ ] AC1 登录用户可以在文案库创建一篇含标题、正文和多个自由文本标签的文案，刷新后数据仍存在。
- [ ] AC2 用户可以搜索或按人工标签筛选文案，并能编辑或经确认删除自己可编辑的文案。
- [ ] AC3 普通成员只能读取自己的文案和团队共享文案，无法修改或删除他人的共享文案；管理员行为符合现有账号规则。
- [ ] AC4 无限画布可以新增文案库节点、选择一篇文案并分别输出冻结的标题和正文。
- [ ] AC5 文案库节点输出可经过 GPT 文本等节点二创，再通过内容组装节点生成现有评审工作区可见的待审查内容。
- [ ] AC6 已保存画布中的文案快照不会因源文案被编辑或删除而在下次运行时静默变化。
- [ ] AC7 批量调度可用手选或标签筛选建立文案池，按稳定顺序循环分配给多个内容任务，并为每个最终运行冻结可追溯的文案快照。
- [ ] AC8 调度预检会在任何付费调用前拒绝缺失或非法的文案绑定配置。
- [ ] AC9 原有画布与批量调度流程仍能加载和运行，不要求迁移已有图数据。
- [ ] AC10 项目既有 lint、TypeScript、build、Trellis baseline 以及新增离线检查全部通过。
- [ ] AC11 本地生产服务刷新后，文案库和画布/批量调度交互通过桌面与移动端浏览器验证。

## Out Of Scope

- AI 自动生成文案库内容或自动给文案打标签。
- 文案版本历史、多人实时协同编辑或富文本编辑器。
- 新建另一套文本模型执行器或另一套待审查内容存储。
- 默认验证中调用真实付费模型或外部发布服务。
