# 修复无限画布缩放与连线视觉回归

## Goal

修复近期无限画布性能优化后出现的视觉回归：让业务连线在未选中时仍保持可识别的流光语义，让媒体图片在缩放全过程持续显示，并按用户最新要求保留 React Flow 原生缩放反馈，同时保留已经取得的可见元素裁剪与分层渲染性能收益。

## Background

- 用户确认本地无限画布经过数次更新后出现连线与媒体问题：未选中连线不再显示流光；选中连线后基础线呈灰色；缩放期间媒体图片暂时消失。用户随后明确撤销缓入缓出需求，要求恢复此前的原生缩放版本。
- 当前本地版本已实施 Canvas 缩放性能优化阶段 1 至 3，包括可见元素裁剪、移动期间暂停边动画、按缩放层级降低节点绘制，以及稳定 viewport 合成层。
- 修复必须针对真实回归原因，不能通过媒体重新挂载、轮询、无意义 fallback 或放弃既有性能优化来掩盖问题。

## Requirements

- R1：画布静止且用户未启用减少动态效果时，可见业务连线应在未选中状态下显示流光；选中连线不得使基础路径退化为灰色，且应保持清晰的选中反馈。
- R2：缩放交互从开始到结束期间，在当前 `full` / `reduced` / `overview` 细节层级本应显示的节点媒体图片必须保持可见且 DOM 身份稳定，不得仅因 viewport 处于移动状态而被隐藏、卸载或重新请求。
- R3：滚轮、触控板、触屏双指及画布缩放控件恢复 React Flow 原生缩放路径，不使用自定义 duration、easing、wheel 目标累计或 route-local Controls。
- R4：缩放和平移期间的性能策略可以暂停昂贵的边滤镜或降低非关键装饰，但不得隐藏节点主体媒体，也不得改变节点几何尺寸、handle 位置、选择、连线、MiniMap、保存节奏或运行状态。
- R5：继续遵守 `prefers-reduced-motion`；减少动态效果模式下取消流光，但必须保留可识别的静态连线和连续可见的媒体。
- R6：范围仅限本地 Canvas 前端渲染与相应的确定性验证，不修改 Canvas API、数据库、调度器、提供商调用或生产部署。

## Acceptance Criteria

- [x] AC1：画布静止时，未选中普通业务连线显示流光；选中前后基础路径均使用业务强调色而非灰色，并有明确选中态。
- [x] AC2：缩放和平移过程中，交互开始前可见且未跨越既有 LOD 隐藏边界的媒体图片持续可见；同一媒体元素的 DOM 身份与资源请求保持稳定，停止交互后无需恢复性显示或重新加载。
- [x] AC3：滚轮、触控板、触屏双指与缩放控件使用 React Flow 原生缩放行为；自定义缓入缓出控制器及其状态、事件入口和专用 Controls 已删除。
- [x] AC4：缩放焦点、节点尺寸、handle 几何、选择、连线、MiniMap、viewport 持久化及运行状态不回归。
- [x] AC5：减少动态效果模式禁用非必要动画，但静态连线和媒体仍正常显示。
- [x] AC6：Canvas 聚焦契约、TypeScript、变更文件 lint、生产构建、本地重启、HTTP smoke 和不调用外部付费服务的浏览器检查通过。

## Out Of Scope

- 修改后端工作流、运行队列、数据模型或媒体存储。
- 为缩放替换 React Flow 或重写整个画布架构。
- 部署到生产环境。
