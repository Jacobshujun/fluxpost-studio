# 灵活画布批量调度 V2

## Goal

将无限画布当前固定的“场景素材 + 多张车型素材 + 可选文案”批量调度改造成用户可配置的两层任务系统。用户可以自行定义主任务和子任务参数、参数来源、展开方式及画布节点字段绑定，并在同类型节点并存时通过自定义节点名称准确识别目标。

## Background

- 当前 V1 调度固定使用 `scene-input`、`vehicle-input`、`prompt-switch`、`image-target`、`content-target` 五个必需角色和一个可选 `copy-input` 角色。
- V1 固定按一张场景图创建一篇内容任务，再按抽取的车型图片创建图片子任务，无法表达人物、场景、车辆角度或其他任意参数组合。
- `CanvasNode` 已保存可选 `label`，节点卡片会显示它，但检查器没有统一的节点名称编辑入口，部分预演和运行信息仍只显示节点类型。
- Canvas schedule、run 和 queue 已通过 JSON 快照持久化，启动操作能原子写入 schedule 与全部子运行；V2 应复用这些能力。

## Requirements

### R1. Two-level task model

- V2 固定为“主任务 -> 子任务”两层，不支持递归嵌套。
- 主任务保存共享参数并负责结果聚合；子任务保存逐项变化的参数并独立执行、记录状态和重试。
- 一个车辆参考图角度必须展开为一个独立子任务，而不是把多个角度合并为一次子任务输入。

### R2. User-defined parameters

- 人物、场景、文案和车辆角度仅是预设示例，不是固定字段。
- 用户可以添加、删除、排序和命名参数，并决定参数属于主任务还是子任务。
- 首版参数类型包括图片、图片组、文本、文案记录、数字、布尔值和枚举。
- 参数来源包括固定值、手工列表、素材库筛选和文案库筛选；不适用的来源不得出现在对应类型中。
- 每个参数可设为固定值、全量逐项展开或随机逐项展开。随机逐项展开支持精确数量与闭区间数量；区间内每个整数等概率，先按参数值去重，再在一次预演中无放回抽取。配置的最大数量超过唯一候选数时必须在预演阶段失败。
- 主任务随机参数每次预演抽样一次；子任务随机参数必须为每个主任务独立抽样，因此不同主任务可以复用候选值，但同一主任务内不得重复。
- 多个逐项参数在所属层级按用户选择的笛卡尔积或按序配对规则展开。笛卡尔积下每个随机参数独立决定数量；按序配对下所有逐项参数从允许数量区间的交集中共享一个数量，交集为空、精确数量冲突或全量参数长度不兼容时预演失败。
- 图片组作为一个值整体注入，不自动拆分。

### R3. Explicit Canvas binding

- 每个参数显式绑定到一个支持批量注入的画布节点配置字段，持久化目标为稳定的 `nodeId + fieldKey`，不得按节点名称猜测。
- 节点注册表声明可注入字段、接受的参数类型和快照注入方式。素材库图片、文案记录等复合快照必须通过明确适配器注入，不允许任意 JSON 路径改写。
- 同一个节点字段只能绑定一个参数；类型不兼容、节点/字段缺失或重复绑定必须在预演前失败。
- 用户显式选择子任务结果节点及输出端口，并可选主任务最终目标节点。子任务可聚合的首版 artifact 类型为文字、图片和视频。

### R4. Node naming

- 所有画布节点均可在节点检查器中编辑自定义名称，名称非空且最多 80 个字符。
- 节点卡片、参数绑定器、预演树、任务树、错误和运行记录优先显示运行快照中的自定义名称。
- 允许重名；选择器在重名或同类型节点场景显示自定义名称、节点类型和短节点 ID。
- 重命名不得改变参数绑定；复制节点、复制画布、模板和运行快照必须保留名称。

### R5. Preflight and immutable launch

- 预演冻结工作流版本、完整画布、参数定义、解析后的素材/文案值、主子任务展开结果、执行目标、聚合策略和预计调用数。
- 启动前重新验证工作流版本、绑定、冻结素材可用性、展开数量和预演指纹；漂移必须拒绝启动。
- 启动继续原子写入 schedule、所有子任务 Canvas run 和 queue 记录，不能只启动部分合法任务。
- 首版沿用每个 schedule 最多 2,000 个子任务的硬上限，并在预演阶段显示总主任务数、总子任务数和模型调用估算。
- 已启动任务不可编辑；用户通过复制任务创建新版本。

### R6. Runtime and aggregation

- 主任务参数注入其所有子任务；子任务参数只注入对应子运行。
- 默认只要至少一个子任务成功即可聚合；另提供“所有子任务必须成功”的严格模式。
- 未配置主任务最终目标时，成功子任务的 artifact 集合直接成为主任务结果。
- 配置主任务目标时，调度器使用成功子任务 artifact 替换冻结图中的子任务结果节点，再运行其下游到主任务目标；不得重新执行已经成功的付费子任务路径。
- 失败子任务可以独立重试。后续重试产生的新候选结果沿用现有草稿保护：未编辑草稿可自动同步，已编辑或审核过的结果必须显式接受。
- 暂停、继续、取消、进程重启恢复和终态子运行唤醒调度器继续复用现有 durable worker 机制。
- 批量调度不得自动执行飞书发布节点。

### R7. Compatibility

- 没有 V2 schema 标识的 schedule 按 V1 读取，已启动 V1 任务继续支持恢复、暂停、取消、重试和结果聚合。
- V1 草稿/预演任务通过“转换为灵活调度”创建 V2 副本，原记录不被原地改写。
- 新建 schedule 默认使用 V2。现有标准十一节点骨架保留为可选预设，但 V2 不依赖固定 scheduler role。
- V2 继续使用现有 `canvas_schedules.data_json`、Canvas run 和 queue 表，不新增数据库表，也不清理历史记录。

## Acceptance Criteria

- [ ] 用户能在同一画布创建任意命名的主任务和子任务参数，并绑定到多个同类型节点中的准确目标字段。
- [ ] “人物固定值 + 场景固定值 + 三张车辆角度图逐项展开”预演为一个主任务和三个独立子任务，每个子任务只收到一个车辆角度。
- [ ] 主层和子层的固定值、笛卡尔积、按序配对、精确/区间随机数量、每主任务独立抽样、批次内随机去重及图片组规则均有确定性测试；随机容量不足、区间无交集、非法配对和重复字段绑定在 provider 调用前失败。
- [ ] 节点重命名、重名、复制、保存、重载和运行快照不会改变现有参数绑定，所有调度界面可区分同类型节点。
- [ ] 预演冻结参数和素材快照；源记录后续修改或删除不会改变已启动任务，工作流或预演漂移会阻止启动。
- [ ] 默认聚合允许部分子任务成功，严格聚合等待全部成功；单子任务重试不会重复执行已成功子任务。
- [ ] 无主目标时能查看聚合 artifact；有主目标时只执行结果节点下游，并保持已编辑草稿的显式候选接受规则。
- [ ] V2 原子启动、2,000 子任务上限、暂停/恢复/取消、进程恢复、owner 隔离和 revision 冲突行为不退化。
- [ ] V1 历史任务继续运行；V1 到 V2 的转换创建副本且不修改原任务。
- [ ] 确定性 Canvas scheduler/workflow 检查、TypeScript、lint、build 和可用的 Trellis baseline 通过，默认验证不调用付费 provider 或飞书写入。

## Out of Scope

- 任意深度或递归子任务。
- 用户脚本、表达式语言或任意 JSONPath 注入。
- 新增参数类型插件市场或跨工作流参数绑定。
- 批量任务自动发布到飞书。
- 修改现有 provider 并发池、计费策略或外部服务配置。
