# 轻量迁移助手

在项目目录打开 PowerShell：

```powershell
cd D:\FluxPost\social-content-studio
npm run migrate
```

默认先显示进度，再显示菜单。打开菜单、查看状态和查看执行记录不会启动迁移。
工具不额外打开后台窗口，也不要求启动网页。

## 菜单

1. 刷新检查结果：确认后读取当前 TOS/OSS 文件清单和数据库任务状态。
   会产生少量云端读取请求，不复制、不修改数据库、不重启应用。
2. 继续切换：确认后检查环境，暂停本地 3001，创建最终备份，补搬缺失文件，
   核对清单，修改已验证的素材地址及 OSS 配置，再按正式启动入口构建和启动，
   最后验收。验收会短暂创建管理员测试会话和两个极小的 OSS 健康检查对象，
   在测试结束后清理；不调用付费模型或发布飞书内容。
3. 查看执行记录：显示阶段、时间、计数与安全错误码，不输出密钥或业务内容。
0. 退出：退出界面，不代表撤销已完成的操作。

直接查看，不进入菜单：

```powershell
npm run migrate -- status
npm run migrate -- logs
```

执行时每个阶段都有开始/完成提示，有文件数或记录数时显示实际计数。长步骤每
15 秒报告已用时间；不会估造百分比或预计完成时间。备份和构建阶段可能暂时没有
新的文件计数，这是工具仍在等待该步骤完成，不表示已经成功。

## 安全边界

- 进度带检查时间，不是实时云端同步。应用继续生产时，缺失文件可能增加。
- `continue` 要求工作区干净；修改过的代码必须先验证并提交。密钥和数据不提交。
- 只更新已验证 OSS 文件对应的地址，历史失效、未知或签名地址保留。日志档案和
  历史飞书 outbox 文件不重写、不重发；它们仍可能包含旧地址。
- `data/tos-pending/` 的历史失败上传文件保留，不自动补传，也不计入云端文件数。
- 不删除 TOS；切换成功后至少保留七天，清理另行确认。
- Ctrl+C 请求在当前步骤结束后停止。数据库修改使用事务；提交成功后不会因为
  退出界面而撤销。不要强行关闭终端或关机。
- 若步骤失败，后续阶段不执行。不自动恢复旧程序、不自动重新复制、不自动重试。
  如果已经停服，必须处理失败或恢复后才能重新使用。锁或未完成记录会阻止重启。
- 不要手动删除 `operation.lock`、覆盖最终备份或编辑事务回退文件。
- 当前备份已验证可完整解码，但没有另一数据库的完整恢复演练；此限制会显示。

## 本地文件

- `data/oss-cutover/config.json`：本次证据和备份的工作区内路径，不包含密钥。
- `data/oss-cutover/state.json`：工具最后的执行阶段和计数。
- `data/oss-cutover/operation.lock`：单实例操作保护。
- 最终备份目录内包含数据库 dump、原始配置、地址修改回退凭据及配置修改收据，
  只在本机保存，不上传 Git；失败后以这些证据判断恢复方式。

## 旧搬运工具

原来本机整批复制仍保留在明确的子命令中，避免误启动：

```powershell
npm run migrate -- copy help
```

默认 `start` / `stop` / `watch` 不再操作旧复制进程。当前已完成云端整批复制，
不要使用旧 `copy start` 重新搬运。
