# 批量调度文案池条件随机去重

## Goal

让 Canvas 批量调度中的文案池像场景素材池一样支持按条件随机抽取，并保证一个批次内每个图文任务获得一条不同的冻结文案，避免同批内容重复使用同一文案。

## Background

- 当前文案池支持手动记录和关键词/AND 标签筛选，但预演会按标题与 id 稳定排序后用 `index % pool.length` 轮询分配。
- 当前轮询在文案少于图文任务时会重复使用文案，不满足批次内去重要求。
- 场景与车型素材已有 `sampleCanvasAssets` 无放回随机抽样能力；调度预演会冻结素材与文案快照，执行阶段不重新读取源库。
- 已保存调度使用 `CanvasScheduleCopyFilter.mode: "manual" | "tags"`，本任务必须保持兼容且不新增数据库迁移。

## Requirements

- R1: 文案池保留“手动选择”，并将现有关键词/AND 标签筛选入口呈现为“条件随机”。
- R2: 预演时从当前批次匹配的文案池中无放回随机抽取，抽取数量等于该批次图文任务数。
- R3: 同一批次的冻结文案 id 必须唯一；不同批次之间不要求去重。
- R4: 匹配文案数少于图文任务数时，预演必须失败并显示当前可用数与所需数，不能循环复用或静默缩减任务。
- R5: 文案在预演时继续冻结完整标题、正文、标签与更新时间；启动和最终合成不得重新读取文案库。
- R6: “重抽本批次”重新抽取该批次的文案和车型素材；“重抽本篇”保留该篇冻结文案，只重抽车型素材。
- R7: 已保存的 `manual | tags` 文案筛选数据和未启用文案池的旧工作流继续可用。

## Acceptance Criteria

- [x] AC1: 条件随机模式可用关键词和多个 AND 标签形成候选池，界面明确显示“条件随机”。
- [x] AC2: 当候选文案数大于或等于图文任务数时，预演结果中的文案 id 在批次内全部唯一。
- [x] AC3: 当候选文案数不足时，预演在创建任何付费任务前返回明确错误，且不会生成循环重复分配。
- [x] AC4: 整批重抽后仍满足批次内唯一，并重新生成文案分配；单篇重抽后该图文任务的文案快照不变。
- [x] AC5: 手动文案池、条件随机文案池、无文案池以及旧五角色 Canvas 工作流均保持兼容。
- [x] AC6: 调度专项验证、TypeScript、相关文件 lint、生产构建与本地生产重启通过；验证不调用付费模型、Feishu 或其他外部生产服务。

## Out Of Scope

- 不要求跨批次或跨调度任务去重。
- 不增加文案使用历史、长期防重复或权重配置。
- 不修改文案库 CRUD、权限模型、数据库表结构或最终内容生成链路。
