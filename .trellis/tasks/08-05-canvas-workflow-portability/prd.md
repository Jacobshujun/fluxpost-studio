# Canvas 跨画板复制与工作流导入导出

## Goal

让桌面端 Canvas 操作者能够像 ComfyUI 一样在 FluxPost 画板之间复制节点片段，并通过版本化 JSON 文件备份或迁移完整工作流。完成本地验证后，将该能力与已完成的 Canvas V2 主任务共享输出一起发布到生产 38。

## Background

- 现有剪贴板可复制节点和内部连线，但工具栏依赖安全上下文剪贴板 API，解析时会丢失 `schedulerRole`，且没有合并容量校验。
- Canvas 已有 owner-scoped 工作流创建 API、图升级和服务端图校验，无需新增数据库结构或导入 API。
- 当前没有工作流文件导入导出入口；运行、调度和媒体二进制不属于可移植工作流图。

## Requirements

- R1：剪贴板 version 1 继续兼容旧载荷，并保留节点配置、位置、尺寸、名称、执行模式和调度角色，以及选中节点之间的内部连线。
- R2：复制同时写当前页面内存剪贴板并尽力写系统剪贴板；工具栏仅在系统剪贴板不可访问时回退到内存载荷，不覆盖已成功读取的非 Canvas 系统剪贴板内容。
- R3：粘贴生成全新节点和连线 ID，锚定鼠标位置或画布中心；合并后超过 200 节点或 600 连线时整次拒绝。
- R4：目标画板已占用唯一调度角色时，清除对应新节点的冲突角色并明确提示，不修改目标原节点。
- R5：剪切只在内存载荷成功保存后删除源节点。
- R6：导出当前可见编辑态为 `<画板名>.fluxpost-workflow.json`，文件包含 `kind`、`version`、`name` 和 `graph`，不包含工作流身份、owner、revision、模板/来源、时间、调度、运行或结果数据。
- R7：导入接受不超过 10 MB 的 FluxPost version 1 JSON，拒绝错误类型、未知版本、无效视口、未知节点/版本、无效端口、悬空连线、循环和超限图。
- R8：合法导入复用 `POST /api/canvas/workflows` 创建 revision 1、非模板、当前用户所有的新画板，成功后立即切换；失败不得创建部分记录。
- R9：默认验证不得调用付费模型、ComfyUI、Seedance、Feishu、Lark 或修改生产运行数据。

## Acceptance Criteria

- [x] 从画板 A 复制带内部连线的多节点片段，切换到画板 B 后可粘贴，节点属性完整且 ID 全新。
- [x] 系统剪贴板拒绝访问时，工具栏仍可通过当前页面内存载荷跨画板粘贴；系统剪贴板成功读取到其他内容时不会粘贴旧节点。
- [x] 调度角色无冲突时保留，有冲突时只清除新节点角色并显示提示。
- [x] 超过画布节点或连线上限时不修改目标图。
- [x] 导出包含自动保存窗口内的当前名称、图和视口，且不泄露工作流/用户/运行元数据。
- [x] 合法文件导入为新画板；错误类型、版本、尺寸或图结构显示明确错误且不发创建请求。
- [x] Canvas workflow、scheduler、TypeScript、lint、build、local restart、HTTP smoke 和完整 Trellis baseline 通过。
- [ ] 完整远程 SHA 通过生产候选验证、零活动任务门禁、备份、部署和发布后身份/健康检查。

## Out Of Scope

- ComfyUI 原生 workflow JSON 兼容。
- 嵌入、复制或迁移媒体二进制。
- 导出批量调度定义、运行历史、运行结果或 provider 任务。
- 扩展移动端节点结构编辑。
- 在生产创建测试画板或触发外部服务。
