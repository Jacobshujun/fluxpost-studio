# 修复批量调度副本名称

## Goal

连续复制无限画布批量调度任务时，名称只保留一个副本标记，并用当前北京时间生成可读的秒级任务编号。

## Background

- `duplicateCanvasSchedule()` 当前直接在来源名称后追加 ` 副本`，所以复制已复制任务会不断叠加该文字。
- 生产运行 SHA `5be0cb988580149037655d4213be6faa835c820d`，当前 GitHub `main` 是本次候选基线。
- 根工作区包含其他未提交工作，本任务必须在独立干净工作树完成。

## Requirements

- R1. 新副本名称使用 `<基础名称> 副本 YYYYMMDD-HHmmss`，时间明确按 `Asia/Shanghai` 生成。
- R2. 生成新名称前，移除尾部一个或多个旧式 `副本`，以及新版 `副本 YYYYMMDD-HHmmss` 标记。
- R3. 名称编号和 `createdAt` 必须来自同一个 `now` 值。
- R4. 不改变复制 API、任务 ID、V1/V2 调度定义、运行时清理、所有权或普通画布工作流复制行为。
- R5. 同一秒内名称允许相同；持久化身份仍由任务 ID 区分。
- R6. 来源名称接近 80 字符上限时，只截短基础名称以容纳完整副本后缀，复制操作不得因此失败。
- R7. 候选必须从最新 `origin/main` 构建，完整验证、推送并按完整 SHA 通过生产候选验证和只读预检。
- R8. 部署必须保留生产环境配置、PostgreSQL、七个持久卷、后台 worker 和受保护服务；失败时恢复发布前版本。

## Acceptance Criteria

- [x] AC1. `任务 A` 复制后名称匹配 `任务 A 副本 YYYYMMDD-HHmmss`。
- [x] AC2. `任务 A 副本`、`任务 A 副本 副本` 和 `任务 A 副本 <旧时间>` 再次复制后都只保留一个副本标记。
- [x] AC3. 名称中的北京时间编号与副本 `createdAt` 表示同一时刻，精确到秒。
- [x] AC4. 80 字符来源名称仍可复制，生成名称不超过 80 字符且保留完整副本后缀。
- [x] AC5. 现有 V2 定义规范化及复制生命周期检查继续通过。
- [x] AC6. 聚焦调度器检查和完整 Trellis 基线通过，不调用付费或外部写入服务。
- [ ] AC7. 远端候选完整 SHA 通过隔离验证、生产预检、部署和部署后健康检查；失败则验证回滚。

## Out Of Scope

- 普通画布工作流、节点复制和其他资源的命名规则。
- 通过数据库查询生成递增序号或保证名称唯一。
- 真实模型、Feishu、TikHub、ComfyUI 或内容生产调用。
