# 技术设计

## URL 状态边界

- 新增共享的客户端 URL 状态工具，负责读取 `window.location.search`、规范化枚举/数组参数、构造稳定查询字符串，并通过 `next/navigation` 的 router replace 写回。
- 页面挂载时先 hydration URL 状态，再开始依赖这些状态的列表请求；首次同步不应把默认值覆盖到地址栏。
- 使用重复查询键表达数组，去重并按输入稳定顺序序列化；默认值省略以保持 URL 简洁。
- 无效实体 ID 由数据加载阶段验证，找不到时选择页面安全默认项；权限仍由 API 校验。

## 页面映射

- 内容台保存项目查询、内容池筛选/排序/标签、当前内容 ID、采集模式/平台。
- 图库保存视图及实体 ID、搜索/标签/可见性/状态/排序、详情资产 ID。
- 审查台保存 `postId`、`sourceBatchId` 和列表筛选。
- 画布保存 `workflowId`、`runId`、节点 ID 和任务/调度面板；图数据与视口仍由服务端工作流持久化。
- 原创、文案库、分发审核、高级配置只保存筛选、当前实体或当前 job/group 等可复现导航状态。

## 兼容与风险

- 保持现有 `/review?postId=...` 和 `sourceBatchId` 链接兼容。
- 不把分发审核编号、Cookie 或未提交内容写入 URL。
- 页面级状态同步失败时保留当前内存状态并显示现有错误，不添加静默 fallback。
